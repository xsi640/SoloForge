# 任务拆解：团队任务看板应用

本文件基于 `code/docs/tech-architecture.md` 生成，与 `api-design.md` 同为阶段 4 测试阶段的输入。

## 1. 实现范围与顺序说明

### 实现范围

覆盖技术架构文档中的全部 7 个模块与公共基础设施，不含任何需求之外的功能。

### 最小可运行闭环

先打通「能登录 → 看到三列看板与卡片 → 新建任务 → 拖拽改状态 → 退出登录」这条链路，它由下列任务构成：

```text
TASK-001 工程骨架
→ TASK-002 数据库与初始化数据
→ TASK-003 公共层
→ TASK-004 登录、登出与当前用户
→ TASK-005 登录校验拦截与账号状态校验
→ TASK-006 看板信息与状态列查询
→ TASK-007 任务创建与详情查询
→ TASK-009 任务状态更新
→ TASK-014 前端骨架、登录页与路由守卫
→ TASK-015 前端看板页：三列与卡片渲染
→ TASK-016 前端拖拽换列
```

闭环完成时，团队已经可以真实使用（记录任务、看状态、拖动推进），后续任务都属于在闭环上补齐能力。

### 实现顺序

1. 基础设施：`TASK-001` → `TASK-002` → `TASK-003`。
2. 后端业务：`TASK-004` 起按依赖推进，其中 `TASK-006` 之后可并行展开 `TASK-007` 至 `TASK-013`。
3. 前端：`TASK-014` 可与 `TASK-006` 之后的后端任务并行，`TASK-015` 之后的页面任务按依赖推进。
4. 收尾：`TASK-022` 在最小闭环跑通后即可准备，不阻塞功能开发。

### 本期不做

以下内容已在需求、UX 或架构阶段明确排除，不进入任务表，也不保留废弃行：

- 任务变更历史、任务归档、看板归档
- 多项目与多看板切换
- 评论、附件、子任务、标签
- 甘特图与统计报表
- 角色与权限分级（管理员仅决定成员管理入口可见性）
- 自助注册、删除成员
- 外部提醒通道（邮件、企业微信、钉钉），提醒仅站内轮询
- 自定义状态列、任务列表分页、HTTPS 与公网访问

| `TASK-TBD-001` | 代码放在什么位置 | 全部任务 | 确认 | 用户确认代码输出到仓库内的 `code/` 目录，与阶段文档同仓便于对照。`TASK-001` 据此落地为 `code/backend`、`code/frontend`，部署产物在 `code/deploy`，验证脚本在 `code/scripts` |

## 6. 人工确认结论

- 当前文档状态：实现已按本文件执行完成，代码位于 `code/`。任务状态已回填，`TASK-001` ~ `TASK-013` 已完成，`TASK-014` ~ `TASK-022` 待浏览器端与真机验证。
- 已执行的实现顺序与闭环：基础设施、后端业务、前端页面、收尾四段推进；最小可运行闭环为「登录 → 三列看板与卡片 → 新建任务 → 拖拽改状态 → 退出登录」。
- 已按默认结论落地的待定项：`TASK-TBD-002` 至 `TASK-TBD-008` 给出的默认值分别是成员管理接口由后端强制校验管理员身份、任务负责人必填、标题与描述有长度上限、被停用账号会话即时失效、截止日期允许为空、截止日期筛选用全部／已超期／临期三个快捷值、当天到期算临期。
- 原待追问的内容：`TASK-TBD-001` 代码目录位置已由用户确认为 `code/`，该项关闭。
