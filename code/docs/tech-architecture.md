# 技术架构：团队任务看板应用

本文件基于 `code/docs/requirement-analysis.md` 生成，是阶段 3B 拆解任务的唯一架构输入。

## 1. 架构目标与约束

### 对应需求的架构目标

| 需求目标 | 架构上的落地方式 |
|---|---|
| 任务可创建、可维护（增删改） | `MODULE-004` 提供任务 CRUD 接口，单表 `task` 承载全部字段 |
| 状态可见可流转（拖拽换列） | `MODULE-005` 以前端交互为主，后端复用 `MODULE-004` 的状态更新接口 `PATCH /api/tasks/{id}/status` |
| 任务可检索（搜索 + 筛选） | `MODULE-006` 在服务端按条件过滤，一次返回全部匹配结果 |
| 到期有提醒（临期 / 超期） | `MODULE-007` 提供查询接口，临期与超期在读取时按 `due_date` 实时计算，不落库 |
| 统一入口（同一看板） | 单看板设计，`board` 表仅一行；所有成员访问同一份数据 |
| 成功标准可验证 | 全部状态存于 `task` 表，任意成员读取同一份数据，任务当前状态与负责人始终可见可查 |

### 非功能性约束

- 部署：内网 Linux 服务器，通过 IP 直接访问，不使用 HTTPS。
- 规模：10 人左右并发使用，任务量小，无分页与横向扩展需求。
- 维护：单人长期维护，架构以够用可维护为准，不引入不必要的中间件与框架。
- 数据：本地嵌入式数据库，数据落盘保存，重启不丢。
- 安全：仅内网可达；密码不可明文存储；会话在服务端校验。

## 2. 交付形态与运行环境

- 交付形态：单体应用。前端构建产物放入后端静态资源目录，由同一个 Java 进程同时提供页面与接口。
- 运行环境：Linux 服务器 + JDK 17，单个 `java -jar` 进程，由 systemd 常驻守护。
- 访问方式：用户通过 `http://<内网IP>:<端口>` 访问，服务器上只有一个进程、一个端口。
- 构建环境：后端 Maven 3.9.x + JDK 17；前端 Node.js 需 22.12 以上（开发机为 v24.14）。
- 数据文件位置：`<工作目录>/data/board.mv.db`，随工作目录一起备份。

## 3. 技术栈与分层

### 分层与职责

| 层 | 职责 | 约束 |
|---|---|---|
| 控制层（controller） | 接收请求、参数校验、返回统一响应体 | 不写业务逻辑，不直接操作数据库 |
| 服务层（service） | 业务规则、事务边界、权限与状态判断 | 一个需求模块对应一个服务接口 |
| 持久层（mapper） | MyBatis 接口 + XML，负责 SQL 与结果映射 | SQL 全部写在 XML 中，不散落在服务层 |
| 实体与传输对象 | 数据库实体、请求对象、响应对象 | 数据库实体不直接作为接口出入参 |
| 公共层（common） | 统一响应体、异常处理、Session 工具、日期与常量 | 不包含任何具体业务规则 |

跨层规则：控制层只依赖服务层；服务层只依赖持久层与公共层；不允许控制层直接调用 Mapper。

## 4. 模块划分与需求模块映射

模块名称与编号原样复用需求文档，不重新命名。

| 编号 | 需求模块 | 后端包 | 前端职责 | 备注 |
|---|---|---|---|---|
| `MODULE-001` | 账号与登录 | `auth/`（登录、会话、当前用户）加 `member/`（成员管理） | 登录页、成员管理页 | 成员管理是账号模块内的子包，不单独成模块 |
| `MODULE-002` | 看板管理 | `board/` | 看板页顶部信息 | 仅维护唯一看板本身 |
| `MODULE-003` | 列管理 | `column/` | 看板三列渲染 | 只提供查询接口，不提供增删改 |
| `MODULE-004` | 任务卡片 | `task/` | 卡片、新建弹层、详情弹层 | 任务字段的唯一归属 |
| `MODULE-005` | 看板视图 | 无独立后端包 | 看板页展示与拖拽 | 以前端交互为主，状态写入复用 `MODULE-004` 接口，避免空壳模块 |
| `MODULE-006` | 检索 | `query/` | 搜索框与筛选条 | 条件过滤在服务端完成 |
| `MODULE-007` | 提醒通知 | `reminder/` | 铃铛与提醒清单 | 只读查询，状态实时计算 |

公共基础：`common/`（统一响应体、全局异常处理、Session 工具、常量与枚举）。

模块边界规则：

- `MODULE-003` 与 `MODULE-002` 的边界：列的查询属于 `MODULE-003`，看板自身信息属于 `MODULE-002`。
- `MODULE-005` 与 `MODULE-004` 的边界：状态字段的数据归属仍为 `MODULE-004`，`MODULE-005` 只触发更新，不另建状态表。
- `MODULE-007` 与 `MODULE-006` 的边界：筛选中的「已超期」属于 `MODULE-006`（用户主动查询），提醒属于 `MODULE-007`（系统主动呈现），两者各自计算、不共享状态。
- `MODULE-001` 的身份校验被其他模块复用，其他模块不得自行实现登录判断。

## 5. 数据与存储

### 存储方式

- 数据库：H2 嵌入式文件模式，JDBC URL 形如 `jdbc:h2:file:./data/board;DB_CLOSE_DELAY=-1`。
- 建表：`schema.sql` 幂等建表（`CREATE TABLE IF NOT EXISTS`），随应用启动执行。
- 初始化数据：看板一行、固定三列（待办 / 进行中 / 完成）在启动时按需写入。
- 备份：定期复制整个 `data/` 目录即可，不引入备份工具。

### 数据表

| 表 | 字段 | 说明 |
|---|---|---|
| `app_user` | id、username（唯一）、display_name、password_hash、is_admin、status（ENABLED / DISABLED）、created_at、updated_at | 成员账号。`is_admin` 仅决定是否可见成员管理入口，不产生任务层面权限差异 |
| `board` | id、name、created_at、updated_at | 单看板，仅一行 |
| `board_column` | id、board_id、code（TODO / DOING / DONE）、name、sort_order | 固定三列，初始化写入，不提供增删改 |
| `task` | id、board_id、column_id、title、assignee_id、priority（HIGH / MEDIUM / LOW）、due_date、description、created_at、updated_at | 任务卡片。状态由 `column_id` 表达，与需求中「状态」字段等价 |

数据规则：

- 任务必须关联到存在的看板与列；`assignee_id` 指向 `app_user`。
- 成员停用后 `app_user` 记录保留，任务上的负责人不变。
- 描述为纯文本，不做富文本。
- 优先级默认 `MEDIUM`。
- 不记录任务变更历史，不设历史表。

## 6. 接口约定

### 通用约定

- 路径前缀 `/api`，请求与响应均为 `application/json; charset=UTF-8`。
- 统一响应体：`{ "code": 0, "message": "ok", "data": ... }`，`code` 为 0 表示成功，非 0 表示业务失败。
- 日期格式 `yyyy-MM-dd`，时间格式 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`。
- 字段命名统一使用 camelCase。

### 鉴权约定

- 登录成功后由服务端创建会话，通过 `JSESSIONID` Cookie 维持；Cookie 设置 HttpOnly 与 SameSite=Lax，因不使用 HTTPS，不设置 Secure。
- 除 `POST /api/auth/login` 外的所有接口都需要登录。
- 每次请求都校验当前账号状态，被停用的账号在下一次请求即被拒绝。
- 未登录或会话失效返回 401，前端据此跳转登录页。

### 错误约定

| HTTP 状态 | 场景 | 前端处理 |
|---|---|---|
| 400 | 参数校验失败（如标题为空、登录名重复） | 展示具体提示，保留用户输入 |
| 401 | 未登录或会话过期 | 跳转登录页 |
| 500 | 服务端异常 | 提示「操作失败，请重试」 |

### 接口清单

字段级定义在阶段 3B 的 `api-design.md` 中给出，此处只确定范围与归属。

| 模块 | 接口 | 用途 |
|---|---|---|
| `MODULE-001` | `POST /api/auth/login` | 登录 |
| `MODULE-001` | `POST /api/auth/logout` | 退出登录 |
| `MODULE-001` | `GET /api/auth/me` | 获取当前登录用户（含是否管理员） |
| `MODULE-001` | `GET /api/members` | 成员列表 |
| `MODULE-001` | `POST /api/members` | 新增成员 |
| `MODULE-001` | `PUT /api/members/{id}/password` | 重置密码 |
| `MODULE-001` | `PUT /api/members/{id}/status` | 停用 / 启用成员 |
| `MODULE-002` | `GET /api/board` | 获取看板信息 |
| `MODULE-003` | `GET /api/board/columns` | 获取状态列 |
| `MODULE-004` | `POST /api/tasks` | 新建任务 |
| `MODULE-004` | `PUT /api/tasks/{id}` | 编辑任务 |
| `MODULE-004` | `DELETE /api/tasks/{id}` | 删除任务 |
| `MODULE-004` | `GET /api/tasks/{id}` | 任务详情 |
| `MODULE-004` | `PATCH /api/tasks/{id}/status` | 更新任务状态（拖拽与详情弹窗共用） |
| `MODULE-006` | `GET /api/tasks` | 按关键词、负责人、优先级、截止日期条件查询任务 |
| `MODULE-007` | `GET /api/reminders/mine` | 获取当前用户的临期与超期任务 |

约定：

- 成员管理接口不提供删除成员的能力。
- 列管理只有查询接口，没有增删改接口。
- 任务查询不支持分页，一次返回全部匹配结果。

## 7. 构建、运行与部署

### 构建

1. 前端：`npm install` 后执行 `npm run build`，产物复制到后端 `src/main/resources/static/`。
2. 后端：`mvn clean package`，产出单个可执行 jar。

### 本地运行

- 启动后端后直接访问本地端口即可，前端产物已包含在同一进程内。
- 前端开发时可用 Vite 开发服务器，通过代理把 `/api` 转发到后端端口。

### 部署

- 服务器目录：`/opt/board/`，内含 `board.jar`、`application.yml`、`data/`。
- 启动命令：`java -jar /opt/board/board.jar`。
- 由 systemd 单元守护，配置失败自动重启与开机自启。
- 配置来源：`application.yml`，允许用环境变量覆盖端口、数据目录与初始管理员账号。

### 首次启动引导

- 启动时检查用户表：若为空，则用配置中的初始管理员账号创建第一个管理员。
- 初始管理员账号与密码通过配置项提供，文档中提示首次登录后立即重置密码。

## 8. 架构决策记录

| 编号 | 决策点 | 背景 | 最终选择 | 被放弃的方案 | 放弃原因 |
|---|---|---|---|---|---|
| `ADR-001` | 架构风格 | 7 个模块边界清晰，单人长期维护 | 按模块分包的单体 | 按层分包；前后端分离 | 按层分包会让同层不同业务混杂，模块与代码位置不再一一对应；前后端分离与「前端产物放进后端」的选择矛盾，且要额外维护进程与跨域 |
| `ADR-002` | 交付与部署 | 内网 Linux，只需一个入口 | 前端产物嵌入后端，`java -jar` 加 systemd | Nginx 分离部署；Docker | 分离部署要维护静态服务与反向代理；Docker 在内网单机上增加一层维护成本 |
| `ADR-003` | 鉴权方式 | 单体应用，无多端需求 | 服务端 Session 加 Cookie | JWT | 需额外维护令牌过期与刷新逻辑，单体内没有收益 |
| `ADR-004` | 持久层 | 用户要求使用 MyBatis | 纯 MyBatis（手写 XML SQL） | MyBatis-Plus；Spring Data JPA | MyBatis-Plus 的自动 CRUD 与用户选择不符；JPA 在嵌入式库上的方言支持一般 |
| `ADR-005` | 数据库 | 需嵌入式、易维护、避免并发写锁 | H2 嵌入式文件模式 | SQLite；MySQL | SQLite 存在并发写锁限制；MySQL 需要独立服务进程 |
| `ADR-006` | 鉴权框架 | 只需要密码哈希与会话校验 | 仅引入 spring-security-crypto 做 BCrypt，会话自建拦截器 | Spring Security 全框架 | 全框架的过滤器链与配置复杂度远超本项目所需 |
| `ADR-007` | 前端样式 | 界面量小但要贴合设计稿 | 手写 CSS | Element Plus | 需覆写主题才能贴近设计稿，体积与配置成本高于收益 |
| `ADR-008` | 提醒实现 | 只要求站内提醒，无实时推送需求 | 前端每 5 分钟轮询，临期与超期在读取时实时计算 | 后端定时任务加提醒状态落库 | 落库会产生状态同步与过期清理问题，实时计算更简单可靠 |
| `ADR-009` | 数据库初始化 | 需要可复现且低维护成本的建表方式 | `schema.sql` 幂等建表加启动引导管理员 | Flyway 迁移框架 | 单库单版本，迁移框架属于过度设计 |
| `ADR-010` | 前端路由 | 仅登录页与看板页两个路由 | hash 模式 | history 模式 | history 需要后端为前端路由增加 fallback 转发，多一处易错配置 |
| `ADR-011` | 前端语言与构建 | 单人维护，降低配置负担 | Vue 3 加 Vite 加 JavaScript | TypeScript | 类型系统收益有限，但增加配置与构建复杂度 |
| `ADR-012` | 后端构建工具 | 与 Spring Boot 生态一致 | Maven | Gradle | 无多模块复杂构建需求，Maven 更通用易排障 |

## 9. 技术风险

| 风险 | 影响 | 应对 |
|---|---|---|
| H2 文件模式在极端并发写入下仍可能串行等待 | 10 人规模下表现为瞬时延迟，不阻塞使用 | 事务保持短小；如后续任务量大幅增长，按 `ADR-005` 的备选切换为 MySQL |
| 会话保存在内存中，服务重启后所有人需重新登录 | 重启后一次重新登录 | 可接受，与「不做记住我」的 UX 结论一致 |
| 数据库文件损坏或误删 | 数据丢失 | 定期复制 `data/` 目录；不使用 H2 内存模式 |
| 单体进程同时承载页面与接口，进程异常会导致整体不可用 | 服务不可访问 | systemd 自动重启；统一异常处理避免进程退出 |
| 不使用 HTTPS，会话 Cookie 在内网明文传输 | 内网抓包可获取会话 | 需求已明确内网 IP 访问、不做 HTTPS；通过限定内网可达降低风险 |
| 初始管理员密码写在配置中 | 配置泄露即账号泄露 | 首次登录后立即重置密码；配置项支持环境变量覆盖 |

## 11. 人工确认结论
