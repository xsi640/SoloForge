# SoloForge

SoloForge 是一个以 AI 时代软件开发工作方法为核心的项目文档与实践仓库，目标是把“想法 → 产品设计 → 研发 → 测试 → 发布”这条链路整理成一套简单、可复用、适合长期坚持的开发方法。

## 项目概览

这个项目的核心目标是：

- 把软件开发过程整理成一套稳定、可复用的工作方法
- 用 AI 提升需求拆解、产品设计、任务分解、测试辅助和文档生成能力
- 让每个阶段都有明确输出，便于执行、协作、复盘与迭代
- 在不追求复杂流程的前提下，尽量保持简单、可验证、可持续

## 为什么建立这个项目

在 AI 时代，软件开发并不是简单地让 AI 直接写代码，而是要把 AI 变成一个真正能帮助人提高效率的协作工具。

SoloForge 的价值在于：

- 把开发过程从“感觉式”切换为“结构化”
- 把任务从“模糊需求”变成“可执行清单”
- 把设计、研发、测试、发布串成一个完整闭环
- 让工作方法可以被反复复用，而不是每次都重做一套流程

## 当前推荐的开发方法

### 1. 需求分析阶段
- 明确要解决的问题
- 确定目标用户和核心价值
- 设定成功标准
- 审核 AI 生成的 idea 草案

### 2. 产品设计与 UI/UX
- 明确页面结构、关键功能与交互流程
- 产出产品设计与 UI/UX 草图说明
- 确认先做什么、后做什么

### 3. 研发阶段
- 输出技术方案简版
- 产出 API 文档
- 生成任务文档，用于 AI 并发开发与任务进度跟踪
- 进行代码实现与文档补充

### 4. 测试阶段
- 制定测试重点和关键路径
- 让 AI 生成测试用例与辅助建议
- 进行人工测试与问题修复

### 5. 发布阶段
- 编译与构建产物
- 准备部署包
- 生成发布说明与回滚方案
- 发布后进行验证

## AI 的使用方式

AI 在这个项目中主要承担：

- 需求拓展与梳理
- 产品结构与交互说明的生成
- API 文档草案
- 任务拆解与并发开发任务的组织
- 任务进度汇总与状态跟踪
- 测试用例生成与问题汇总
- 发布说明与回滚建议

AI 不承担最终决策，最终判断和责任仍然由人来负责。

## 设计原则

- 简单优先：不要为了流程而流程
- 可复用：每个阶段都有明确可复用输出
- 可验证：每个目标都有验收标准
- 可迭代：每次迭代都留下可追踪记录
- 可协作：AI 能协助，人负责判断与交付

## 适用场景

这个工作方法适用于：

- 一个人维护的小型项目
- 需要 AI 协作开发的场景
- 希望把开发过程标准化但又不想过度复杂化的团队或个人
- 需要长期积累开发经验、模板和文档的项目

## 使用建议

如果你要直接用这个方法，建议按下面顺序推进：

1. 先做需求分析
2. 再做产品设计与 UI/UX
3. 然后形成技术方案、API 说明和任务文档
4. 接着执行开发与测试
5. 最后进行发布与复盘
