# UI/UX Design Skill

## 目标

帮助人完成一套清晰、可用、视觉一致的 UI/UX 设计。

本 Skill 只关注界面和用户体验，不负责：

- 项目基本信息
- 产品立项分析
- 技术方案
- 数据库和 API 设计
- 研发任务拆解
- 测试和发布计划

核心流程是：

```text
明确界面目标
→ AI 辅助梳理用户流程
→ 整理页面结构
→ 设计关键交互和页面状态
→ 使用 pen.dev/stitch 辅助生成界面
→ 人工调整和确认
→ 形成 UI/UX 设计稿
```

## 阶段 1 输入文件

开始阶段 2 前，必须先读取阶段 1 的最终需求分析文档：

```text
docs/stages/01-requirement-analysis/requirement-analysis.md
```

不要读取阶段 1 的填写模板作为正式需求输入。若该文件不存在，或仍包含未处理的未确定事项，应先回到阶段 1 完成确认。

## 适用场景

- 需要设计一个新页面或一组页面
- 需要优化现有页面的操作流程
- 需要让 AI 帮助补全用户流程和页面状态
- 需要使用 pen.dev/stitch 辅助探索界面方案
- 需要输出可供后续实现参考的 UI/UX 设计

## 先告诉人怎么做

### 第 1 步：读取阶段 1 需求并明确界面目标

先读取 `docs/stages/01-requirement-analysis/requirement-analysis.md`，再明确本次要设计的界面或功能。

人只需要提供最少的信息：

- 要设计哪个界面或功能
- 用户在界面中要完成什么任务
- 当前界面或流程有什么问题
- 有没有已知的设计限制或参考方向

不需要填写项目名称、项目背景、技术栈或其他基本信息。

### 第 2 步：让 AI 辅助梳理用户流程

可以只告诉 AI 用户目标，让 AI 协助生成：

- 用户主流程
- 必要的操作步骤
- 用户可能遇到的分支
- 中断、失败和返回路径
- 流程完成后的反馈

AI 生成流程后，人需要确认它是否符合真实使用场景。AI 不应擅自确定关键业务规则。

### 第 3 步：整理页面结构

根据用户流程确定需要哪些页面或界面状态。每个页面至少描述：

- 页面目标
- 页面主要区域
- 信息层级
- 主要操作
- 次要操作
- 页面跳转关系

优先设计完成核心任务所需的页面，不要为了页面数量而增加无用内容。

### 第 4 步：补充关键交互和状态

对每个关键操作说明：

- 用户做什么
- 界面如何响应
- 成功后显示什么
- 失败后显示什么
- 用户还能如何继续

逐个页面检查：

- 默认状态
- 首次使用状态
- 加载状态
- 空状态
- 编辑状态
- 操作中状态
- 成功状态
- 错误状态
- 无权限状态（如适用）
- 网络异常状态（如适用）

### 第 5 步：使用 pen.dev/stitch 辅助设计

可以使用 pen.dev/stitch 辅助完成界面探索和设计迭代，例如：

- 根据页面结构生成初版界面
- 根据用户流程生成多个页面状态
- 尝试不同布局和信息层级
- 生成不同视觉风格的方案
- 根据反馈调整组件、间距和交互

使用工具时，提示词应尽量包含：

- 页面目标
- 目标用户的核心任务
- 页面主要区域
- 主要和次要操作
- 必须展示的信息
- 需要覆盖的页面状态
- 视觉风格或参考方向

工具生成的结果只是设计草案，必须由人检查内容、流程、可用性和视觉一致性。

### 第 6 步：人工调整和确认

人需要重点确认：

- 用户是否能快速理解页面
- 核心操作是否容易发现
- 操作顺序是否自然
- 页面信息是否过多或过少
- 成功、失败和异常反馈是否明确
- 不同页面的视觉和交互是否一致
- 设计稿是否覆盖关键状态

### 第 7 步：整理最终设计稿

最终保留：

- 用户流程
- 页面清单
- 页面结构说明
- 关键交互说明
- 页面状态说明
- 视觉和组件方向
- 设计工具生成的结果及人工调整记录
- 最终设计稿、截图或链接

## AI 的提问策略

AI 应优先询问会影响用户体验的问题：

1. 用户在这个界面中最想完成什么？
2. 完成任务必须经过哪些步骤？
3. 哪个操作是主要操作，哪个是次要操作？
4. 用户操作成功后需要看到什么？
5. 操作失败或数据为空时怎么办？
6. 用户是否可能中断、返回或重复操作？
7. 有没有必须遵循的视觉参考？

不要把对话重点放在项目名称、技术选型或后端实现上。

## 可直接复制的提示词

### 版本 A：让 AI 梳理用户流程

```text
我现在进行 UI/UX 设计。

需要设计的界面或功能：
[填写界面或功能]

用户想完成的事情：
[填写用户目标]

当前遇到的问题：
[填写现有问题，可选]

请先不要写技术方案，也不要补充项目基本信息。
请帮我：
1. 梳理一条最简洁的用户主流程；
2. 列出必要的分支、异常和中断情况；
3. 说明每一步用户看到什么、可以做什么；
4. 指出需要我确认的流程问题。
```

### 版本 B：让 pen.dev/stitch 生成界面草案

```text
请根据下面的 UI/UX 要求生成界面设计草案：

页面目标：
[填写页面目标]

用户核心任务：
[填写用户任务]

页面主要区域：
[填写页面区域]

主要操作：
[填写主要操作]

次要操作：
[填写次要操作]

需要覆盖的状态：
[默认、加载、空、成功、错误等]

视觉方向：
[填写风格、颜色、布局或参考产品]

请优先保证信息层级清晰、主要操作突出、流程简单，并同时考虑各个页面状态。
```

### 版本 C：让 AI 审查设计稿

```text
请审查下面的 UI/UX 设计：

用户流程：
[粘贴用户流程]

页面说明：
[粘贴页面结构]

设计截图或链接：
[提供截图或链接]

请重点检查：
1. 用户是否能顺利完成核心任务；
2. 页面信息层级是否清楚；
3. 主要操作是否容易发现；
4. 是否遗漏加载、空、成功、错误等状态；
5. 交互反馈是否明确；
6. 页面之间的视觉和交互是否一致。
请区分“必须修改”“建议优化”和“待确认问题”。
```

## 检查清单

### 流程

- [ ] 用户目标清楚
- [ ] 主流程可以走通
- [ ] 必要分支已考虑
- [ ] 失败、中断和返回路径已考虑

### 页面

- [ ] 页面目标清楚
- [ ] 页面结构和信息层级清楚
- [ ] 主要操作容易发现
- [ ] 主要操作和次要操作有区分
- [ ] 页面跳转关系清楚

### 状态和反馈

- [ ] 默认状态已设计
- [ ] 加载状态已设计
- [ ] 空状态已设计
- [ ] 操作中状态已设计
- [ ] 成功反馈已设计
- [ ] 错误反馈已设计
- [ ] 无权限和网络异常已按需设计

### 视觉和工具

- [ ] 页面视觉风格一致
- [ ] 组件、间距和层级一致
- [ ] 已使用 pen.dev/stitch 或其他工具辅助探索（如适用）
- [ ] 工具生成结果已经人工调整
- [ ] 设计稿、截图或链接已保存

## 不要做的事

- 不要在阶段 2 填写与 UI/UX 无关的项目基本信息
- 不要跳过用户流程直接堆页面
- 不要只设计正常状态而忽略异常状态
- 不要把工具生成的界面直接当作最终设计
- 不要让 AI 自行决定关键业务规则
- 不要为了视觉效果牺牲可用性和信息清晰度
- 不要在本阶段展开技术实现、API 或数据库设计

## 最终交付物

阶段 2 最终只需要保留：

- 用户流程
- 页面清单
- 页面结构说明
- 关键交互说明
- 页面状态说明
- 视觉和组件方向
- 设计稿、截图或链接
- AI 辅助和人工调整记录

## 目标语气

AI 在这个阶段的语气应该是：

- 以用户任务和使用体验为中心
- 先梳理流程，再提出界面方案
- 少量、准确地提出问题
- 清楚区分建议和已确认设计
- 对工具生成的结果保持审查态度
- 最终帮助人形成简单、清晰、可用的 UI/UX 设计
