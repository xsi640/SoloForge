# Product Design Skill

## 目标

阶段 2 由两个严格有先后关系的子阶段组成：

```text
阶段 2A：UX
读取 requirement-analysis.md
→ 与用户交互式询问
→ 生成并确认 ux-design.md

阶段 2B：UI
读取 ux-design.md
→ AI 生成 UI 提示词
→ 使用 pen.dev/stitch 生成效果图
→ 人工调整并确认 ui-design.md
```

本 Skill 只负责 UX 和 UI，不负责项目基本信息、技术方案、数据库、API、研发任务、测试或发布计划。

阶段 2A 最终文件：

阶段 2B 最终文件：

## 阶段 2A：UX 设计

### UX 的职责

UX 阶段只处理：

- 用户目标
- 用户角色和使用场景
- 用户主流程
- 分支、异常、中断和返回路径
- 页面职责
- 页面之间的关系
- 关键交互
- 页面状态
- 用户反馈

UX 阶段不处理：

- 色彩
- 字体
- 图标
- 阴影
- 视觉风格
- 组件美化

### UX 协作流程

#### 第 1 步：读取需求文档

AI 必须先读取：

```text
docs/stages/01-requirement-analysis/requirement-analysis.md
```

先总结需求中与用户体验有关的目标、用户、任务和约束，不要求用户重新填写项目名称等基本信息。

#### 第 2 步：交互式询问

AI 不应一次性生成完整 UX 文档，而应按轮次询问用户。每轮只询问少量最关键的问题，并在用户回答后更新当前理解。

推荐询问顺序：

1. 用户最重要的任务是什么？
2. 用户从哪里开始？
3. 用户需要经过哪些步骤？
4. 每一步需要看到什么、做什么？
5. 操作成功后如何反馈？
6. 空数据、错误、中断和返回时如何继续？

#### 第 3 步：生成 UX 草稿

信息足够后，AI 生成 UX 草稿，必须包含：

- UX 设计目标
- 用户角色和场景
- 主流程
- 分支流程
- 异常、中断和返回路径
- 页面职责
- 关键交互
- 页面状态
- 用户反馈
- UX 待确认事项

#### 第 4 步：逐项处理 UX 待确认事项

未确认事项不能只列出后直接结束。AI 必须逐项询问用户，并将每项处理为：

- 确认
- 排除
- 延后
- 继续追问

#### 第 5 步：保存 UX 文档

只有用户确认 UX 草稿后，才能保存：

```text
docs/stages/02-product-design/ux-design.md
```

### UX 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UX 任务 | `UX-###` | `UX-001` |
| 用户角色 | `USER-###` | `USER-001` |
| 用户流程步骤 | `FLOW-###-##` | `FLOW-001-01` |
| 分支流程 | `BRANCH-###` | `BRANCH-001` |
| 异常情况 | `ERROR-###` | `ERROR-001` |
| 页面 | `PAGE-###` | `PAGE-001` |
| 交互 | `INTERACTION-###` | `INTERACTION-001` |
| 页面状态 | `STATE-###` | `STATE-001` |
| 内容提示 | `CONTENT-###` | `CONTENT-001` |
| 待确认事项 | `UX-TBD-###` | `UX-TBD-001` |

## 阶段 2B：UI 设计

### UI 的输入

UI 阶段必须读取已确认的：

```text
docs/stages/02-product-design/ux-design.md
```

如果 UI 设计中发现用户流程或页面职责有问题，必须回到阶段 2A 修改 UX，不得在 UI 阶段擅自改变。

### UI 协作流程

#### 第 1 步：提取 UX 信息

AI 从 UX 文档提取：

- 页面编号和页面职责
- 页面主要区域
- 信息层级
- 主要和次要操作
- 页面状态
- 交互反馈
- UX 验收标准

#### 第 2 步：生成 UI 提示词

AI 为每个页面和页面状态生成提示词。每条提示词必须包含：

- UI 编号
- UX 编号
- 页面编号
- 状态编号
- 页面目标
- 页面结构和信息层级
- 主要和次要操作
- 当前页面状态
- 视觉风格
- 布局、色彩、字体和组件规范
- 8px 间距体系
- WCAG 2.2 AA 对比度要求
- 键盘焦点和触控目标要求
- 可用性和无障碍要求
- 不得改变的 UX 约束

#### 第 3 步：使用 pen.dev/stitch

将 UI 提示词交给 `pen.dev/stitch`，用于：

- 生成页面初稿
- 生成不同页面状态
- 探索布局和视觉风格
- 迭代颜色、字体、间距和组件表现

每次生成都必须记录：

- UI 编号
- UX 编号
- 页面编号
- 状态编号
- 工具名称
- 版本号
- 使用的提示词
- 效果图或链接
- 是否采纳

#### 第 4 步：应用 UI 设计规范

UI 文档至少要明确：

- 页面栅格和边距
- 基础间距体系
- 色彩及状态色
- 字体字号、字重和行高
- 按钮、输入框、卡片、列表等组件状态
- 加载、空、成功、错误状态的表现
- 主要操作的视觉优先级
- 文字与背景的对比度
- 键盘焦点状态
- 触控目标尺寸
- 不同页面的视觉一致性

默认设计标准：

- 间距优先使用 8px 体系
- 普通文字与背景对比度至少达到 WCAG 2.2 AA 的 4.5:1
- 大字号文字与背景对比度至少达到 3:1
- 非文字 UI 组件和图形与相邻颜色对比度至少达到 3:1
- 键盘可操作元素必须有清晰的焦点状态
- 触控操作目标建议不小于 44×44px

如果存在无法满足的标准，必须记录例外原因，并由人确认。

#### 第 5 步：人工审阅和迭代

人必须检查效果图是否：

- 符合 UX 文档
- 支持完整用户流程
- 突出主要操作
- 正确表现页面状态
- 保持页面视觉一致
- 具备足够的可读性和可用性

不符合时，AI 重新生成提示词或在 `pen.dev/stitch` 中迭代，并保留版本记录。

#### 第 6 步：保存 UI 文档

确认效果图和规范后，保存：

```text
docs/stages/02-product-design/ui-design.md
```

### UI 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UI 设计任务 | `UI-###` | `UI-001` |
| 颜色 | `COLOR-###` | `COLOR-001` |
| 字体 | `TYPE-###` | `TYPE-001` |
| 组件 | `COMPONENT-###` | `COMPONENT-001` |
| 设计版本 | `V#` | `V1`、`V2` |
| 待确认事项 | `UI-TBD-###` | `UI-TBD-001` |

UI 必须关联 UX 编号，例如：

```text
UI-001
→ UX-001
→ PAGE-001
→ STATE-001
```

## 可直接复制的提示词

### UX 交互式询问

```text
我现在开始阶段 2A：UX 设计。

请先读取并理解：
docs/stages/01-requirement-analysis/requirement-analysis.md

不要询问项目名称、项目背景或技术方案。
请按轮次协助我：
1. 先总结需求中的用户、目标和核心任务；
2. 每轮只问少量最关键的 UX 问题；
3. 根据我的回答逐步梳理用户主流程；
4. 补充分支、异常、中断、返回和页面状态；
5. 生成 UX 草稿让我确认；
6. 将所有待确认事项逐项询问处理；
7. 确认完成后输出 ux-design.md。
```

### 从 UX 生成 UI 提示词

```text
我现在开始阶段 2B：UI 设计。

请读取已确认的：
docs/stages/02-product-design/ux-design.md

请不要改变 UX 文档中的用户流程、页面职责和交互逻辑。
请为每个页面和关键状态生成 pen.dev/stitch 提示词，要求每条提示词包含：
- UI 编号
- UX 编号
- 页面编号
- 状态编号
- 页面结构和信息层级
- 主要和次要操作
- 视觉风格
- 布局、颜色、字体、间距和组件规范
- 可用性与无障碍要求

最后输出可直接使用的 UI 提示词和编号对应表。
```

### UI 效果图审查

```text
请审查以下 UI 效果图是否符合 UX 文档：

UX 文档：
[粘贴 ux-design.md]

UI 编号和效果图：
[粘贴编号、截图或链接]

请检查：
1. 用户流程是否被正确表达；
2. 页面职责和信息层级是否正确；
3. 主要操作是否突出；
4. 默认、加载、空、成功和错误状态是否完整；
5. 色彩、字体、间距和组件是否符合设计规范；
6. 页面之间是否保持视觉一致；
7. 是否存在可用性、可读性或无障碍问题。
请区分必须修改、建议优化和待确认问题。
```

## 阶段 2 完成条件

### UX

- [ ] 已读取 `requirement-analysis.md`

- [ ] 主流程、分支、异常和中断路径已确认
- [ ] 页面职责和状态已确认
- [ ] UX 待确认事项已逐项处理
- [ ] `ux-design.md` 已保存并人工确认

- [ ] 已读取已确认的 `ux-design.md`
- [ ] UI 提示词由 UX 文档生成
- [ ] 每条提示词都有 UX、页面和状态编号
- [ ] 已使用 pen.dev/stitch 生成或迭代效果图
- [ ] 效果图版本和提示词已记录
- [ ] 设计规范已记录
- [ ] 8px 间距体系已确认或记录例外
- [ ] WCAG 2.2 AA 对比度已检查
- [ ] 键盘焦点状态已检查
- [ ] 触控目标尺寸已检查
- [ ] 关键页面状态已覆盖
- [ ] UI 没有改变已确认的 UX 流程
- [ ] UI 待确认事项已逐项处理
- [ ] `ui-design.md` 已保存并人工确认
