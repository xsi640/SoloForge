# 宠物档案 App UX 设计文档

> UX 编号：UX-001  
> 状态：已确认  
> 输入文档：`docs/stages/01-requirement-analysis/requirement-analysis.md`

## 1. UX 设计目标

帮助养宠用户以宠物为中心，集中管理多只宠物的生活记录、病例、相册、提醒和时间轴。

UX 设计重点：

- 让用户可以快速查看所有宠物的近期内容
- 让用户能够进入某只宠物的独立档案
- 让所有新增内容明确关联到具体宠物
- 让生活记录、病例、相册、提醒和时间轴之间的关系清楚
- 让用户可以持续记录宠物约半年或更长时间

## 2. 用户与使用场景

### 用户角色

- 编号：`USER-001`
- 养猫、狗、爬宠等宠物的个人用户
- 可能同时管理多只宠物
- 希望长期记录宠物成长和健康状况

### 主要使用场景

1. 用户打开 App，查看所有宠物最近发生的内容。
2. 用户切换到某只宠物，查看该宠物的档案和健康摘要。
3. 用户添加日记、体重变化、生日、就医事件或其他生活记录。
4. 用户创建病例并在之后逐步补充医疗信息。
5. 用户设置疫苗、驱虫等周期性提醒。
6. 用户完成提醒后记录完成日期和备注。
7. 用户通过时间轴回顾宠物的完整记录。

## 3. 模块边界

| 模块 | UX 职责 |
|---|---|
| 宠物列表 | 展示和管理用户的全部宠物 |
| 全部宠物时间轴 | 汇总所有宠物的内容 |
| 宠物档案首页 | 展示单只宠物的基本信息、健康摘要和快捷操作 |
| 生活记录 | 记录宠物日常事件和变化，包含日记等记录类型 |
| 病例 | 独立管理完整医疗信息 |
| 相册 | 独立查看所有模块中的图片和视频 |
| 提醒 | 管理周期性健康和日常事项 |
| 时间轴 | 汇总展示所有内容，已完成提醒也包含在内 |

### 边界规则

- 日记是生活记录的一种类型，不是独立的新增模块。
- 生活记录中的就医事件可以关联到已有病例或新建病例。
- 病例是独立模块，用于保存完整医疗信息。
- 自行用药可以直接记录为生活记录，不强制创建病例。
- 相册支持独立上传，也汇总其他模块中的图片和视频。
- 未完成的提醒不进入时间轴，完成后的提醒进入时间轴。
- 所有记录必须关联到具体宠物。

## 5. 用户流程

### FLOW-001 首次创建宠物

| 步骤编号 | 用户动作 | 系统响应 | 下一步 |
|---|---|---|---|
| `FLOW-001-01` | 首次打开 App | 检测到当前没有宠物 | 进入添加宠物 |
| `FLOW-001-02` | 填写宠物档案 | 校验全部字段 | 提交档案 |
| `FLOW-001-03` | 提交宠物档案 | 创建第一只宠物 | 进入新宠物档案首页 |
| `FLOW-001-04` | 查看新宠物档案首页 | 展示基本信息、健康摘要和快捷操作 | 可进入全部宠物时间轴 |

首次创建宠物时需要填写：

- 名字
- 头像 / 照片
- 物种
- 品种
- 性别
- 生日 / 出生日期
- 到家日期
- 当前体重
- 绝育情况
- 备注

### FLOW-002 查看全部宠物时间轴

| 步骤编号 | 用户动作 | 系统响应 | 下一步 |
|---|---|---|---|
| `FLOW-002-01` | 打开 App | 进入全部宠物时间轴 | 查看内容 |
| `FLOW-002-02` | 浏览内容 | 按内容发生时间倒序展示 | 点击内容或筛选 |
| `FLOW-002-03` | 使用宠物筛选 | 仅显示指定宠物内容 | 继续浏览或查看详情 |
| `FLOW-002-04` | 使用内容类型筛选 | 仅显示指定类型内容 | 继续浏览或查看详情 |
| `FLOW-002-05` | 点击内容 | 进入对应内容详情页 | 查看、编辑或删除 |

时间轴内容包括：

- 生活记录
- 病例
- 相册内容
- 已完成提醒

每条内容显示：

- 宠物头像
- 宠物名字
- 内容类型
- 内容摘要
- 内容发生日期

### FLOW-003 切换和进入宠物档案

用户可以通过以下方式进入某只宠物：

1. 点击时间轴内容中的宠物头像或名字；
2. 使用顶部宠物切换器；
3. 从宠物列表中选择宠物。

进入后到达 `PAGE-004` 宠物档案首页。

### FLOW-004 新增宠物

1. 用户打开顶部宠物切换器。
2. 用户进入 `PAGE-001` 宠物列表。
3. 用户点击“添加宠物”。
4. 系统进入 `PAGE-003` 添加宠物。
5. 用户填写全部宠物档案信息。
6. 用户提交。
7. 系统创建新宠物。
8. 系统直接进入新宠物的档案首页。

### FLOW-005 添加生活记录

1. 用户进入某只宠物档案首页。
2. 用户点击“添加生活记录”。
3. 系统进入 `PAGE-006`，展示记录类型。
4. 用户选择记录类型。
5. 系统进入 `PAGE-007`，展示对应表单。
6. 用户填写并提交。
7. 系统保存记录并关联当前宠物。
8. 记录进入该宠物时间轴和全部宠物时间轴。

生活记录类型：

- 日记
- 体重变化
- 生日 / 到家日
- 绝育 / 发情
- 就医事件
- 自行用药
- 自定义事件

#### FLOW-005-01 日记记录

- 文字必须填写
- 图片和视频可以为空
- 日期默认当前日期
- 用户可以修改日期
- 创建后可以编辑并补充图片或视频

### FLOW-006 添加病例

1. 用户进入某只宠物档案首页。
2. 用户点击“新建病例”。
3. 系统进入 `PAGE-010` 添加病例。
4. 用户填写就医日期和就医原因。
5. 用户可以补充诊断、处理方式、用药、备注和附件。
6. 用户提交病例。
7. 系统创建病例并关联当前宠物。
8. 用户之后可以进入病例详情继续补充。

病例必填：

- 就医日期
- 就医原因

病例可选并可后续补充：

- 诊断信息
- 处理方式
- 用药信息
- 医疗备注
- 图片或附件

#### FLOW-006-01 就医事件关联病例

| 分支编号 | 触发条件 | 用户选择 | 系统响应 | 流程结果 |
|---|---|---|---|---|
| `BRANCH-006-01` | 添加就医事件 | 选择已有病例 | 将生活记录关联到病例 | 事件和病例均可查看 |
| `BRANCH-006-02` | 添加就医事件 | 新建病例 | 创建病例并自动关联 | 事件和病例均可查看 |

### FLOW-007 添加提醒

1. 用户进入某只宠物档案首页。
2. 用户点击“添加提醒”。
3. 用户选择提醒类型。
4. 系统根据物种和提醒类型生成默认周期。
5. 用户确认或修改周期。
6. 用户设置下一次提醒日期。
7. 系统保存提醒。
8. 到期时发送系统通知。
9. 用户进入待处理提醒列表。
10. 用户完成事项并标记完成。
11. 系统记录完成日期和备注。
12. 已完成提醒进入时间轴。

提醒类型包括：

- 疫苗
- 驱虫
- 体检
- 喂药
- 洗澡
- 剪指甲
- 自定义事项

### FLOW-008 查看相册

1. 用户进入某只宠物档案首页。
2. 用户点击“查看相册”。
3. 系统展示该宠物所有模块中的图片和视频。
4. 用户可以独立上传图片或视频。
5. 用户点击媒体后查看媒体详情或来源记录。

## 6. 页面职责与快捷操作

### PAGE-002 全部宠物时间轴

- 默认 App 入口
- 展示所有宠物内容
- 默认时间倒序
- 支持按宠物筛选
- 支持按内容类型筛选
- 顶部提供宠物切换器
- 不提供直接新增内容入口

### PAGE-004 宠物档案首页

展示：

- 宠物基本信息
- 当前体重
- 最近一次病例
- 当前用药
- 最近一次完成的提醒
- 即将到期的提醒
- 已逾期的提醒

当前用药同时展示：

- 病例中的用药
- 生活记录中的自行用药

两种来源需要明确区分。

快捷操作：

- 添加生活记录
- 新建病例
- 添加提醒
- 查看时间轴
- 查看相册

### PAGE-006 添加生活记录

先选择记录类型，再进入对应表单，避免所有类型共用一个复杂表单。

### PAGE-011 提醒列表

至少分为：

- 待处理
- 已完成
- 已逾期

完成提醒时只允许补充备注，不添加图片或附件。

## 10. UX 验收标准

- [ ] 首次用户必须先创建宠物
- [ ] 新增宠物成功后进入新宠物档案首页
- [ ] App 默认进入全部宠物时间轴
- [ ] 全部宠物时间轴按时间倒序展示
- [ ] 时间轴支持按宠物筛选
- [ ] 时间轴支持按内容类型筛选
- [ ] 每条内容显示所属宠物
- [ ] 新增内容只能从具体宠物档案发起
- [ ] 生活记录先选择类型，再填写对应内容
- [ ] 日记文字必填，图片和视频可为空
- [ ] 日记日期默认当前日期且允许修改
- [ ] 就医事件可以关联已有病例或新建病例
- [ ] 病例允许先填写部分信息并后续补充
- [ ] 提醒默认周期可以修改
- [ ] 提醒完成后只能添加备注并记录完成日期
- [ ] 未完成提醒不进入时间轴

- [ ] 宠物档案首页显示完整健康摘要
- [ ] 所有记录都关联到具体宠物
- [ ] 所有模块支持编辑和删除
- [ ] 空、筛选无结果、逾期、通知关闭等状态已说明
- [ ] 未涉及 UI 颜色、字体和视觉效果
