# 阶段 2：产品设计

## 阶段目标

阶段 2 分为两个严格有先后关系的步骤：

```text
阶段 2A：UX 设计
读取阶段 1 需求分析
→ 与用户交互式澄清
→ 生成并确认 UX 文档

阶段 2B：UI 设计
读取 UX 文档
→ AI 生成 UI 提示词
→ 使用 pen.dev/stitch 生成界面效果图
→ 人工调整并确认 UI 文档
```

阶段 2 只关注用户体验和界面设计，不填写项目基本信息，也不展开技术方案、数据库、API、研发任务、测试和发布计划。

## 固定文件

阶段 1 输入：

```text
docs/stages/01-requirement-analysis/requirement-analysis.md
```

阶段 2A UX：

```text
docs/stages/02-product-design/ux-design.md
docs/stages/02-product-design/ux-design-template.md
```

阶段 2B UI：

```text
docs/stages/02-product-design/ui-design.md
docs/stages/02-product-design/ui-design-template.md
```

入口模板：[product-design-template.md](product-design-template.md)

如果 `requirement-analysis.md` 不存在，或阶段 1 仍有未处理的未确定事项，应先回到阶段 1，不能直接开始阶段 2。

# 阶段 2A：UX 设计

## 目标

把阶段 1 的需求转化为清晰的用户体验和交互逻辑，形成可以被用户确认的 UX 文档。

UX 阶段关注：

- 用户目标
- 用户流程
- 页面职责
- 页面之间的关系
- 关键交互
- 分支、异常和中断路径
- 页面状态
- 用户反馈

UX 阶段暂不关注：

- 颜色
- 字体
- 图标
- 阴影
- 视觉风格
- 组件美化

## UX 操作流程

### 第 1 步：读取阶段 1 文档

AI 必须先读取：

```text
docs/stages/01-requirement-analysis/requirement-analysis.md
```

AI 先总结与本次设计有关的用户、目标和需求，不要重新要求用户填写项目名称等基本信息。

### 第 2 步：交互式询问用户

AI 不应直接编造完整 UX，而应围绕用户体验逐轮询问：

1. 用户最重要的任务是什么？
2. 用户从哪里开始？
3. 用户需要经过哪些步骤？
4. 用户每一步需要看到什么、做什么？
5. 用户操作成功后如何反馈？
6. 用户遇到空数据、错误或中断时如何继续？

每轮只询问少量最关键的问题。用户回答后，AI 更新当前理解，再继续询问下一组问题。

### 第 3 步：AI 生成 UX 草稿

信息足够后，AI 生成 UX 草稿，至少包含：

- UX 设计目标
- 用户角色和场景
- 主流程
- 分支流程
- 异常、中断和返回路径
- 页面职责
- 关键交互
- 页面状态
- 用户反馈
- UX 待确认事项

### 第 4 步：逐项确认 UX 待定事项

UX 草稿中的待确认事项必须逐项询问用户，不能仅列出后直接定稿。每项必须处理为：

- 确认
- 排除
- 延后
- 继续追问

### 第 5 步：保存 UX 文档

用户确认后，将最终文档保存为：

```text
docs/stages/02-product-design/ux-design.md
```

## UX 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UX 设计任务 | `UX-###` | `UX-001` |
| 用户角色 | `USER-###` | `USER-001` |
| 用户流程 | `FLOW-###-##` | `FLOW-001-01` |
| 分支流程 | `BRANCH-###` | `BRANCH-001` |
| 异常情况 | `ERROR-###` | `ERROR-001` |
| 页面 | `PAGE-###` | `PAGE-001` |
| 交互 | `INTERACTION-###` | `INTERACTION-001` |
| 页面状态 | `STATE-###` | `STATE-001` |
| 内容提示 | `CONTENT-###` | `CONTENT-001` |
| 待确认事项 | `UX-TBD-###` | `UX-TBD-001` |

同一对象在 UX 文档、UI 提示词和效果图中必须保持同一编号。

# 阶段 2B：UI 设计

## 目标

根据已确认的 `ux-design.md`，生成 UI 设计提示词，并使用 `pen.dev/stitch` 辅助生成界面效果图，再经过人工调整形成 UI 文档。

UI 阶段不能重新改变 UX 中已经确认的用户流程、页面职责和关键交互。如果发现 UX 有问题，应回到阶段 2A 修订 UX 文档。

## UI 操作流程

### 第 1 步：读取 UX 文档

AI 必须先读取：

```text
docs/stages/02-product-design/ux-design.md
```

提取：

- 页面编号
- 页面职责
- 页面主要区域
- 主要和次要操作
- 页面状态
- 交互反馈
- UX 验收标准

### 第 2 步：生成 UI 设计提示词

AI 根据 UX 文档为每个页面和状态生成提示词。每条提示词至少包含：

- 对应 UX 编号
- 对应页面编号
- 页面目标
- 页面结构和信息层级
- 主要操作和次要操作
- 当前页面状态
- 视觉风格
- 布局、色彩、字体和组件规范
- 可用性和无障碍要求
- 不得改变的交互约束

### 第 3 步：使用 pen.dev/stitch 生成效果图

将 AI 生成的提示词交给 `pen.dev/stitch`，用于：

- 生成页面初稿
- 生成不同页面状态
- 探索布局和视觉风格
- 迭代颜色、字体、间距和组件表现

每次生成都必须记录：

- UI 编号
- 对应页面编号
- 对应状态编号
- 工具名称
- 版本号
- 使用的提示词
- 效果图或链接
- 是否采纳

### 第 4 步：应用设计规范

UI 文档至少要明确以下规范：

- 页面栅格和边距
- 基础间距体系
- 色彩及状态色
- 字体字号、字重和行高
- 按钮、输入框、卡片、列表等组件状态
- 加载、空、成功、错误状态的表现
- 主要操作的视觉优先级
- 文字和背景的对比度
- 键盘焦点状态
- 触控目标尺寸
- 不同页面之间的视觉一致性

默认设计标准：

- 间距优先使用 8px 体系
- 普通文字与背景对比度至少达到 WCAG 2.2 AA 的 4.5:1
- 大字号文字与背景对比度至少达到 3:1
- 非文字 UI 组件和图形与相邻颜色对比度至少达到 3:1
- 键盘可操作元素必须有清晰的焦点状态
- 触控操作目标建议不小于 44×44px

如果项目有特殊限制或无法满足某项标准，必须在 UI 文档中记录例外并由人确认。

### 第 5 步：人工审阅和迭代

人需要检查效果图是否：

- 符合 UX 文档
- 支持完整用户流程
- 突出主要操作
- 正确表现页面状态
- 保持页面视觉一致
- 具备足够的可读性和可用性

不符合时，AI 重新生成提示词，或在 `pen.dev/stitch` 中迭代。每轮修改保留版本记录。

### 第 6 步：保存 UI 文档

确认效果图和规范后，将最终文档保存为：

```text
docs/stages/02-product-design/ui-design.md
```

## UI 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UI 设计任务 | `UI-###` | `UI-001` |
| 颜色 | `COLOR-###` | `COLOR-001` |
| 字体 | `TYPE-###` | `TYPE-001` |
| 组件 | `COMPONENT-###` | `COMPONENT-001` |
| 设计版本 | `V#` | `V1`、`V2` |
| UI 待确认事项 | `UI-TBD-###` | `UI-TBD-001` |

UI 编号必须引用对应的 UX 页面编号和状态编号，例如：

```text
UI-001
→ UX-001
→ PAGE-001
→ STATE-001
```

## 阶段 2 总检查清单

### UX 完成条件

- [ ] 已读取阶段 1 的 `requirement-analysis.md`
- [ ] 已通过交互式询问澄清用户目标和流程
- [ ] 主流程可以完整走通
- [ ] 分支、异常、中断和返回路径已说明
- [ ] 页面职责已明确
- [ ] 页面状态和反馈已说明
- [ ] UX 待确认事项已逐项处理
- [ ] `ux-design.md` 已保存并人工确认

### UI 完成条件

- [ ] 已读取已确认的 `ux-design.md`
- [ ] UI 提示词由 UX 文档生成
- [ ] 每个提示词都有 UX、页面和状态编号
- [ ] 已使用 pen.dev/stitch 生成或迭代效果图
- [ ] 效果图版本和提示词已记录
- [ ] 色彩、字体、间距和组件规范已记录
- [ ] 默认、加载、空、成功和错误状态已覆盖
- [ ] 设计结果没有改变已确认的 UX 流程
- [ ] UI 待确认事项已逐项处理
- [ ] `ui-design.md` 已保存并人工确认

## 最终交付物

阶段 2 完成后，固定产出：

1. `docs/stages/02-product-design/ux-design.md`
2. `docs/stages/02-product-design/ui-design.md`
3. UI 设计提示词
4. pen.dev/stitch 生成的效果图、链接或导出文件
5. UX/UI 编号对应关系
6. UI 设计规范和版本记录
