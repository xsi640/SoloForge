# 需求分析文档结构（阶段 1）

> 说明：这份文件不是给用户填写的模板，而是阶段 1 最终文档 `requirement-analysis.md` 的章节结构参考。
>
> AI 通过交互式询问收集信息，并按照下面的结构自动生成最终需求分析文档。用户不需要预先填写任何模板。

## 生成规则

AI 在生成最终文档时：

1. 只使用交互过程中用户确认过的信息
2. 不清楚的内容标记为“待确认”，不凭空编造
3. 每个未确定事项都必须在文档中体现出最终处理结果
4. 文档语言简洁、可执行、可验证

## 目标文档结构

### 1. 项目概述

- 项目要做什么
- 核心方向
- 一句话说明产品定位

### 2. 目标用户

- 主要使用者是谁
- 使用场景
- 用户具备的前提条件

### 3. 要解决的问题

- 当前痛点
- 为什么值得解决

### 4. 需求目标

- 按核心目标逐条列出
- 每条目标说明用户能获得什么

### 5. 成功标准

- 用户在完成后能做到什么
- 判断需求完成的可验证标准

### 6. 范围与边界

- 必做：本次一定要完成的内容
- 暂不做：明确排除的内容

### 7. 约束与风险

- 主要限制：时间、技术、资源、规则等
- 主要风险：需求变动、技术难度、依赖问题等

### 8. 未确定事项处理结果

| 编号 | 未确定事项 | 影响范围 | 处理方式 | 最终结论 |
|---|---|---|---|---|
| U-01 |  |  | 确认 / 排除 / 延后 / 继续追问 |  |

### 9. 人工确认结论

- 用户已确认的内容
- 明确延期的事项及后续处理方式
- 阶段完成判断
